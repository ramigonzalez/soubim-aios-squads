# Story 13.12 — Meeting Thumbnails

**Story ID:** 13.12
**Epic:** E13 — Recording Ingestion
**Priority:** Medium | **Effort:** 5 SP (estimate)
**Status:** Ready for Review
**Type:** Feature (backend worker job + migration + frontend)
**Requested by:** Rami — thumbnails on the Fathom meetings page (`/settings/integrations/fathom`)

---

## Description

Fathom's API has no thumbnail field (the `/meetings` items have no image and the share page has no `og:image`), so we generate our own from the stored video. A worker job `thumbnail` lets `ffmpeg` read one frame straight from a short-lived presigned URL (seek before input, so the whole file is never downloaded), scales it to 640 px wide and stores it at `org/<org>/sources/<id>/thumbnail.jpg`. `sources.thumbnail_key` marks it done. The thumbnail is served as a presigned GET only on paths that already passed the access + 12.4 visibility checks, exactly like the recording link.

## Acceptance Criteria

### Generation
- [x] New worker job type `thumbnail` (retries with the queue's backoff, 3 attempts, then gives up; logged)
- [x] Enqueued after a Fathom import stores the video (13.4, and the 13.9 webhook path, which uses the same import job) and after a manual upload `complete` with a video (13.5); not for transcript-only uploads
- [x] Enqueue never raises and a failing thumbnail job never fails the import/upload nor marks the meeting failed (the job carries `source_id` in its payload, not in `jobs.source_id`)
- [x] ffmpeg reads the video from a presigned URL (15 min), `-ss` before `-i`, frame at min(60 s, 10 % of the duration) (duration from ffprobe), falling back to the first frame; `scale=640:-2 -q:v 4`, timeouts on ffmpeg (120 s) and ffprobe (30 s)
- [x] ffmpeg is wrapped in `render_thumbnail()` so tests fake it; tests need neither ffmpeg nor network
- [x] `ffmpeg` added to the backend `Dockerfile` (apt)

### Data
- [x] Migration `019_story_13_12` (down_revision `018_story_12_8`): nullable `sources.thumbnail_key`; up/down/up tested on a throwaway DB (dropped afterwards)

### Serving
- [x] `thumbnail_url` (presigned GET, 6 h, or `null`) in: meeting viewer (`GET /sources/{id}/meeting`), History items (`source.thumbnail_url` of project items), Fathom meetings list (`imports[].thumbnail_url`), Ingestion list and history
- [x] Storage disabled or no thumbnail: `null`
- [x] Another organization's internal meeting: 404 on the viewer, and absent from every list (the lists were already visibility-filtered)

### Backfill
- [x] `scripts/generate_thumbnails.py` with `--dry-run`; enqueues jobs, or generates here with `--inline`; skips meetings with no stored video, with a thumbnail, or with a queued/running job (safe to re-run)

### Frontend
- [x] Fathom meetings page: imported meetings show the thumbnail; not-imported ones (and imported ones still without a thumbnail, or whose link failed to load) show a neutral placeholder with duration and platform (Meet / Zoom / Teams from Fathom's `meeting_url`, when known)
- [x] History meeting group header (`SourceGroupAccordion`): small thumbnail in place of the source icon
- [x] Meeting viewer: thumbnail as the `<video poster>`
- [x] `loading="lazy"`, fixed 16:9 box (no layout shift), alt text; pt-BR + en i18n; parity test green

## Dev Notes

- Backend: `app/services/thumbnails.py` (render, generate, enqueue, thumbnail_url), `storage.thumbnail_key()`, worker handler `thumbnail`, `fathom_import.meeting_platform()` (host match, so `evilzoom.us` is not Zoom).

- Smoke test: `render_thumbnail` against the 98-minute local sample (`data/`): frame at 60 s, 25.9 KB JPEG, 0.1 s.

## Assumptions & gaps (pending confirmation)

- [ ] **Not-imported Fathom meetings get a placeholder only.** Their video is not stored, so no thumbnail can be made without downloading it from Fathom; confirm that is acceptable.
- [ ] **One frame, no choice.** A frame at min(60 s, 10 %) can be a blank slide or a camera-off screen; no "pick another frame" feature (phase 2 if wanted).
- [ ] **Thumbnails are not deleted with the meeting.** Deleting a source does not remove its recording from storage today either; the bucket lifecycle rule (13.1) covers both under `org/`.
- [ ] **Platform comes from Fathom's `meeting_url`.** If Fathom omits it for a meeting, only the duration shows. The field name `meeting_url` follows Fathom's documented meeting object; not verified against a live response in this story (no external calls).
- [ ] **Local-disk recordings (pre-13.1) get no thumbnail.** Only recordings in object storage are covered.
- [ ] **The worker image needs ffmpeg.** On Railway this arrives with the new image; a worker started from an old image fails the job (retries, then gives up quietly) and meetings simply have no thumbnail.
- [ ] **Unused `MeetingGroup` molecule not touched.** It is not rendered by any page; the History header is `SourceGroupAccordion`.
