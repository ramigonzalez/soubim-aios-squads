# Story 12.2 — Organization-Scoped Authorization

**Story ID:** 12.2
**Epic:** E12 — Organizations & Client Access
**Priority:** Critical | **Effort:** 8 SP (estimate)
**Status:** Ready for Review
**Type:** Feature (security)
**Requested by:** Rami — client access without leaking other companies' data

---

## Problem Statement

Access checks today are a mix of the global `director` role and project membership:
1. `_check_project_access` (`app/api/routes/project_items.py`) lets any `director` see any project.
2. Ingestion endpoints (`app/api/routes/ingestion.py`) list sources of **all** projects for directors.
3. The meeting viewer and recording links (`app/api/routes/meetings.py`, `app/services/recordings.py`, Story 7.13) reuse `_check_project_access`.
4. V1 `/decisions` routes (`app/api/routes/decisions.py`) have no project access check at all on `GET /decisions/{id}`.

With several companies in one database, any of these returns another organization's data.

## Acceptance Criteria

- [x] One access service: "can this user, in their active organization, read / write / admin this project / source / item?" — used by every route (`app/services/access.py`; no active organization yet → union of the user's organizations, see Assumptions)
- [x] A user sees a project only if their organization owns it or it is shared with their organization (12.3) — ownership done; sharing is one extra condition in `project_access_level` / `accessible_projects_filter` (12.3)
- [x] Ingestion queue, history, items, digest, milestones, shared links, meeting viewer and recording links all go through the service
- [x] Global `director` checks replaced by organization roles (`admin`/`owner`); `users.role` no longer used for authorization (backend; the frontend still gates admin UI on `user.role`, see Gaps)
- [x] **Isolation test suite**: two organizations with data; every list/detail endpoint returns nothing of the other organization (403/404) — `tests/unit/test_org_isolation.py`
- [x] V1 `/decisions` endpoints either secured or removed (they are deprecated) — secured

## Access rules (implemented)

| Who | Level on a project |
|-----|--------------------|
| `owner` / `admin` of the organization that owns the project | `admin` |
| `member` of that organization **and** assigned to the project (`project_members`) | `write` |
| anyone else (other organizations, no organization, project without owner) | `none` |

| Endpoint group | Needs |
|----------------|-------|
| Projects list / `GET /auth/me` + login project list | only accessible projects |
| Project detail, items list/detail, milestones, digest, participants list, stages list, V1 decisions list/detail, meeting viewer (+ recording link), curation status | `read` |
| Create / edit items (`is_done`, statement), participants add/edit/delete, stages set/edit, document upload, Tactiq webhook, V1 decision PATCH (stub) | `write` |
| Milestone toggle, project edit/archive, share links create/list/revoke, ingestion approve/reject/retry/delete/batch, upload-to-storage | `admin` |
| Create project | `owner`/`admin` of some organization; the project is owned by the first such organization |
| `/api/admin/scheduler/status`, `POST /sources/sync` (platform-wide) | `owner`/`admin` of souBIM (platform operator) |
| Ingestion list / history / count | sources of accessible projects only |
| Public by design | `/api/shared/*` (share token), `/api/recordings/*` (signed link, issued only after the check), health, login |

Errors: project routes → 404 if the project does not exist, 403 if no access or level too low.
Source routes (ingestion, meeting viewer, curation) and V1 decision detail → 404 when the source/decision
belongs to a project the user cannot see (does not reveal it exists), 403 when visible but level too low.
Batch approve/reject skips sources the user does not administer (same as missing ids).

## Assumptions & gaps

Each item: chosen option — alternatives — who should confirm.

1. **Organization `member` needs a project assignment.** Members only see projects they are assigned to in `project_members`; owners/admins see every project of their organization. Reason: the 12.1 backfill made *every* existing user (incl. legacy `client` users) a souBIM member — an org-wide rule would have shown them all souBIM projects. This keeps today's behaviour exactly (directors→admin see all, architects/clients see assigned). — Alt: every member reads every project of the organization (simpler; matches "user sees a project if their organization owns it" literally). — **Rami / @architect** (also decides how 12.3 shared projects apply to members).
2. **Role → permission mapping.** `owner` = `admin` (no owner-only action yet). Mutations that required `director` before stay admin-only; item edits, participants and stages stay open to anyone with project access (today's semantics) = `write` for assigned members. — Alt: a `reviewer` role / participants+stages admin-only. — **Rami**.
3. **No active-organization switch (12.5).** A user acts across the union of their organizations' projects. — Alt: restrict to the primary organization until 12.5. — **Rami** (12.5).
4. **No membership → nothing.** A user without organization gets empty lists / 403, even with the legacy `director` role. — confirmed by task brief.
5. **`projects.owner_organization_id` NOT NULL** (migration `008_story_12_2`). Every creation path sets it (API create requires an admin membership; demo seed creates souBIM before the projects). Projects still without an owner are assigned to souBIM during the upgrade (same rule as the 006 backfill); downgrade makes the column nullable again. — Alt: keep nullable and rely on the service (it already denies orphan projects). — **@architect**.
6. **Platform-wide endpoints** (`/api/admin/scheduler/status`, `POST /api/sources/sync`) require owner/admin of the souBIM organization (platform operator), not `users.role`. — Alt: a `users.is_superuser` flag / any organization admin. — **Rami**.
7. **Tactiq webhook** (`POST /api/webhooks/transcript`) requires a JWT user with `write` on the payload's project (it was already behind the JWT middleware; the access check runs before the idempotency lookup). Signature verification (`x_tactiq_signature`) is still not implemented — pre-existing gap. — **@architect**.
8. **Source routes answer 404 for other organizations' sources** (meeting viewer, ingestion mutations, curation) instead of 403. `test_meetings_api::test_non_member_is_forbidden` now expects 404. — Alt: 403 everywhere. — **@qa**.
9. **`GET /auth/me` / login project list** now excludes archived projects for everyone (before: only directors' list excluded them). — minor, **@po**.
10. **Gap — frontend**: admin UI still gated on `user.role === 'director'` (`Navigation.tsx`, `Ingestion.tsx`, `ProjectDetail.tsx`). Today directors are exactly the souBIM admins (12.1 backfill), so nothing changes for current users; a future org admin without the `director` role would get a 403-safe but hidden UI. Next step: use `GET /api/organizations/me` roles (or a per-project `access_level` field) — not done to keep scope. — **Rami** (12.5 likely).
11. **Gap — `users.role` still exists** and is still issued in the JWT/`/auth/me`; it is no longer read by any authorization check in the backend. Deprecation/removal is a follow-up.
12. **Gap — @architect review** of `app/services/access.py` and the isolation suite is required before merge (Dev Notes).

### Findings

| # | Severity | Finding | Status |
|---|----------|---------|--------|
| F1 | High | **Gmail poller routed the platform mailbox to any organization's project**: `EmailMatcherService.match_project` matched labels/subjects against every non-archived project of every organization, so another organization could name a project after a common subject word and receive souBIM's emails. | Fixed — only projects owned by the platform organization (souBIM, the mailbox owner) are candidates. Test `test_email_matching_only_considers_platform_projects`. |
| F2 | High | **Drive folder hijack**: any organization admin could set `projects.drive_folder_id` to a souBIM Drive folder id; the Drive monitor (platform service account) would then ingest souBIM's files into that organization's project, and curation upload would write into souBIM's folder. | Fixed — setting/changing `drive_folder_id` (create and PATCH) requires platform admin; re-sending the current value is allowed. No change for current users (all admins are souBIM admins). Test `test_drive_folder_only_set_by_platform_admins`. |
| F3 | Low | Tactiq webhook idempotency returned the `source_id` of an existing source with the same `webhook_id` even when it belonged to another project/organization (id disclosure). | Fixed — 409 without the id when the duplicate belongs to another project. Test `test_webhook_id_of_other_organization_is_not_revealed`. |
| F4 | Low | Project routes answer 404 (missing) vs 403 (exists, no access): reveals that a project UUID exists. Accepted by the story (UUIDs are not guessable); source/decision routes already answer 404. | Accepted — recommendation R1. |
| F5 | Info | `GET /api/shared/milestones/{token}` still serves archived projects; a 6 h recording link stays valid after access is revoked. | Pre-existing / by design — recommendation R3. |

No IDOR found: every child lookup (item, participant, stage, share link) filters on the authorized URL project; source-based routes derive the project from the source.

### Recommendations

- **R1** — Use 404 for "no access" on project routes too (one rule everywhere), once the frontend handles it.
- **R2** — When per-organization mailboxes / Drive credentials exist (12.x), replace the platform-organization restriction (F1/F2) with "projects of the credential's organization".
- **R3** — Hide share links of archived projects; consider a shorter recording-link TTL.
- **R4** — Tactiq webhook signature verification (`x_tactiq_signature`) is still unimplemented (gap 7).
- **R5** — Frontend admin UI still gated on `user.role` (gap 10); expose a per-project `access_level` so organization admins without the legacy `director` role get the UI.
- **R6** — Role model (gaps 1–2) unchanged by the review; members-see-assigned-only remains the safer default for the 12.1 backfill.
