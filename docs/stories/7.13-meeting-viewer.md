# Story 7.13 — Meeting Viewer: Recording + Transcript at the Item's Timestamp

**Story ID:** 7.13
**Epic:** E7 — Multi-Source Ingestion Pipeline
**Priority:** High | **Effort:** 3 SP
**Status:** Ready for Review
**Type:** Feature
**Requested by:** Rami — feedback on the first real meeting (D/SEASON, 2026-09-04)

---

## Description

From an item there was no way to see or hear the moment it came from. "00:33:40 in recording" was plain text and the transcript only existed outside the app (a local comparison viewer in `data/`, which the web app cannot open: browsers block `file://` links from web pages, and the video must be served).

This story adds an in-app **Meeting viewer** (`/meetings/:sourceId?t=<seconds>`): the recording and the meeting transcript side by side, the transcript following playback, click a turn to seek. Items and meeting headers link to it at the right moment. Meetings without a video open transcript-only, scrolled to and highlighting the turn at `t`.

**Out of scope:** comparing several transcripts of the same meeting side by side (Fathom vs re-transcription) — the app stores one transcript per meeting; this belongs with extraction versions (Story 7.16). Production storage for recordings (see Dev Notes).

## Acceptance Criteria

### Backend
- [x] `GET /api/sources/{id}/meeting` (authenticated, project access check): title, date, duration, summary, transcript, recording
- [x] Recording is `{type: "file", url}` for a stored file, `{type: "external", url}` for `sources.recording_url` (e.g. Fathom share link), or `null`
- [x] Stored file link is signed (HMAC with the JWT secret) and expires after 6 h — a `<video>` element cannot send the Bearer token
- [x] `GET /api/recordings/{id}?expires&signature` streams the file with Range support (seeking); 403 on bad/expired/other-source signature, 404 when no file
- [x] `sources.recording_url` column — Alembic `005_story_7_13`
- [x] `scripts/attach_recording.py SOURCE_ID FILE|URL` — copies a video to `uploads/recordings/<source_id>.<ext>` or sets the external link
- [x] `uploads/` git-ignored (recordings are large client files)

### Frontend
- [x] Route `/meetings/:sourceId` (protected) → `MeetingViewer` page: back to project, title, date, duration
- [x] Stored recording: video + transcript; transcript follows playback (toggle "Follow the recording"; manual scroll pauses following 4 s); click a turn → seek and play; opens at `?t`
- [x] External recording: "Open recording" link + transcript
- [x] No recording: transcript only, turn at `?t` highlighted and scrolled into view
- [x] Uncertain speakers (⚠️ + reason) shown in the transcript
- [x] Item modal: "HH:MM:SS in recording" links to the viewer at that second (items with a V2 source); Transcript tab has "Open in meeting"
- [x] Meeting header in Project History: "Meeting" link to the viewer (V2 sources only)

## Dev Notes

- **Production storage is open:** recordings are ~760 MB per 98-min meeting. Local dev stores them in `uploads/recordings/`. Before deploying, decide between Google Drive (already integrated for curation) and S3/object storage; the signed-link route is the single place to change.
- Labels are in English to match the rest of the UI; Story 11.1 (i18n) will translate them.
- Transcript parsing (`lib/transcript.ts`) expects Fathom's format (`M:SS - Name (Company)` + indented text); the Timeline now reuses its timestamp parser.
- Run backend tests with `TEST_DATABASE_URL=sqlite://` (the default fixture drops the dev DB tables — see Story 7.10).
