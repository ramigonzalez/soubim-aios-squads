# Story 13.18 — Tactiq Transcripts via Zapier with a Personal Ingest Token

## Story

As a **user who records with Tactiq**, I want my transcripts to reach DecisionLog automatically through Zapier, without a login token that expires every week, so that Tactiq meetings land in Ingestão like Fathom meetings.

## Context (current behaviour, verified)

- `POST /api/webhooks/transcript` (`app/api/routes/webhooks.py`):
  - It requires a **user JWT** (global middleware) plus `project_id` in the payload with write access.
  - It also requires the static `X-Tactiq-Secret` header in production (7.19).
- Tactiq has no webhook of its own. The only push path is Zapier ("Meeting Transcript Is Ready" → "Webhooks by Zapier"), which can send static headers only (7.19 findings).
- A Zap cannot refresh a 7-day JWT, so **today the endpoint cannot be used from Zapier in practice** (7.19 gap).
- One global secret identifies nobody: the created Source needs an owner user and organization (12.4).

## Acceptance Criteria (draft)

- [ ] **Personal ingest token:**
  - A user creates it in Configurações > Integrações > Tactiq ("Gerar token") and sees it **once**.
  - Only a hash is stored, with the user, the organization and a last-used date.
  - It can be revoked and regenerated.
- [ ] **New endpoint** `POST /api/webhooks/tactiq` (public path, no JWT):
  - Auth: `Authorization: Bearer <ingest token>`. A wrong or revoked token gets 401.
  - It is rate limited (13.11).
  - The Source is created as the token's user and organization, with `internal` visibility and status pending.
- [ ] **Project choice:**
  - Reuse the 13.16 rules: the meeting title and participants are matched against the user's projects. Exactly one match → that project.
  - Zero or several matches → Unassigned (same rows and statuses in Ingestão as Fathom).
  - A `project_id` in the payload, if present and writable, wins.
- [ ] **Idempotency:** the same Tactiq meeting id is not imported twice.
- [ ] **Setup guide** on the Tactiq settings page: the Zap steps, the URL, the header, and a sample payload mapping.
- [ ] **The old endpoint** `POST /api/webhooks/transcript` stays as it is (JWT + secret) for manual tests, or it is removed (question 2).
- [ ] pt-BR and en i18n.
- [ ] Tests: token create/revoke/hash, 401 cases, routing outcomes, idempotency, rate limit.

## Out of scope (phase 2)

- A Tactiq API or signed webhooks, if Tactiq ever offers them.
- Organization-level tokens shared by a team.
