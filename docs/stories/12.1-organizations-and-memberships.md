# Story 12.1 — Organizations & Memberships

**Story ID:** 12.1
**Epic:** E12 — Organizations & Client Access
**Priority:** Critical | **Effort:** 5 SP
**Status:** Ready for Review
**Type:** Feature
**Requested by:** Rami — "each company is an org: souBIM and DIMAS are both organizations"

---

## Description

DecisionLog has no organization concept: `users.role` is global (`director`, `architect`, `client`), projects have members (`project_members`), and every director sees every project. Introduce **organizations** and **memberships** as the base of multi-company access. Every company is an organization (souBIM, DIMAS, future AEC firms); a user belongs to one or more organizations with a role in each.

**Out of scope:** authorization changes (12.2), project sharing (12.3), meeting visibility (12.4), invitations UI (12.5).

## Acceptance Criteria

- [x] `organizations` table: id, name, slug (unique), created_at
- [x] `organization_members`: user_id, organization_id (composite PK — a user joins an organization once), role (`owner` / `admin` / `member`, CHECK), created_at
- [x] `projects.owner_organization_id` (FK, `ON DELETE RESTRICT`, indexed) — nullable until 12.2 makes every path set it
- [x] Alembic `006_story_12_1` with backfill: create "souBIM", every non-deleted user becomes a member (`director` → `admin`, others → `member`), every project owned by souBIM; idempotent; downgrade removes it all
- [x] `GET /api/organizations/me` returns the user's organizations and role
- [x] New projects (`POST /api/projects/`) are owned by the creator's primary organization
- [x] Demo seed creates souBIM with all users and projects (`ensure_default_organization`)
- [x] Tests: backfill rules (service + migration SQL on PostgreSQL), idempotency, membership uniqueness, multiple organizations, endpoint, project ownership

## Dev Notes

- Keep `users.role` during the transition; 12.2 moves checks to organization roles and then deprecates it.
- Client people (e.g. Débora at DIMAS) are members of **their own** organization (DIMAS), not guests in souBIM; access to souBIM projects comes from project sharing (12.3).
- A user can belong to several organizations (consultants, people changing companies) — the "active organization" is chosen in 12.5.
- Decided (Rami, 2026-10-05): start with `owner/admin/member`; add `reviewer` only if 12.6 needs it.
- **Primary organization** (default until 12.5's switcher): oldest membership; ties (same transaction — PostgreSQL `now()` is per transaction) broken by strongest role, then id.
- Migration tests import the migration file with a stand-in `alembic` module: the backend's local `alembic/` folder shadows the package on import.
- Reference: `app/database/models.py` (`User`, `Project`, `ProjectMember`), migrations `alembic/versions/00*`.
