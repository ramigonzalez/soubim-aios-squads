# Story 13.11 — Rate Limiting

**Story ID:** 13.11
**Epic:** E13 — Recording Ingestion (security follow-up of 12.5 and 13.9)
**Priority:** Medium | **Effort:** 3 SP (estimate)
**Status:** Ready for Review
**Type:** Security hardening (backend, small frontend change)
**Requested by:** Rami — the open "no rate limiting" findings of the 12.5 and 13.9 security reviews

---

## Description

Standard rate limiting for the FastAPI backend, replacing the old in-memory limiter that only covered login (and was off when `DEBUG=true`). Library: `slowapi` (0.1.9) on top of `limits`. In-memory counters by default; shared Redis counters when `RATE_LIMIT_STORAGE_URI` is set, so limits hold across several Railway instances.

## Acceptance Criteria

- [x] `slowapi` pinned in `requirements.txt` (plus `redis` for the shared storage)
- [x] Storage in-memory by default; `RATE_LIMIT_STORAGE_URI` (e.g. `redis://...`) shares limits across instances (documented in `DEPLOYMENT_RAILWAY.md`)
- [x] `RATE_LIMIT_ENABLED` global switch (default true); the test suite sets it to false
- [x] Client key = real client IP; `X-Forwarded-For` is trusted only with `TRUSTED_PROXY=true` (entry `TRUSTED_PROXY_HOPS` from the right, validated as an IP, else the socket peer); authenticated API calls are keyed by user id
- [x] Limits configurable via settings (table below), defaults documented
- [x] 429 + `Retry-After` header + JSON `detail` (and `retry_after` seconds)
- [x] `/api/health` (and `/docs`, `/openapi.json`, `/redoc`) exempt
- [x] Frontend: friendly pt-BR / en message on 429 for login and the invitation page; i18n parity test green
- [x] No DB query in the limiter path; one counter increment per request

## Limits (defaults)

| Scope | Key | Setting | Default |
|-------|-----|---------|---------|
| `POST /api/auth/login` | IP | `RATE_LIMIT_LOGIN_IP` | 30/minute |
| `POST /api/auth/login` | email (lower-cased) | `RATE_LIMIT_LOGIN_EMAIL_MINUTE` / `_HOUR` | 5/minute and 20/hour |
| `/api/invitations/public/*` | IP | `RATE_LIMIT_INVITATION` | 10/minute |
| `/api/fathom/callback` | IP | `RATE_LIMIT_OAUTH_CALLBACK` | 20/minute |
| `/api/fathom/webhook/{id}` | connection id (IP if the id is malformed) | `RATE_LIMIT_WEBHOOK` | 120/minute |
| `/api/webhooks/*` (Tactiq) | IP | `RATE_LIMIT_WEBHOOK` | 120/minute |
| `/api/shared/*`, `/api/recordings/*` | IP | `RATE_LIMIT_PUBLIC_LINK` | 60/minute |
| Other `/api/*` | user id from a valid JWT, else IP | `RATE_LIMIT_DEFAULT` | 600/minute |
| `/api/health`, docs | exempt | | |

## Dev Notes

- `app/api/middleware/rate_limit.py`: one `http` middleware (registered after auth and before CORS, so it runs before the auth DB lookup and its 429 still gets CORS headers). It picks a rule by path prefix and calls slowapi's `Limiter.limiter.hit` (fixed-window strategy: one counter per key). The user id comes from the JWT signature check only (no DB). Limits are read from settings at request time.
- The per-email login limit is `enforce_login_email_limit`, called at the top of the login route (the body is already parsed there). It counts every attempt, successful or not, so one address cannot be hammered from many IPs. The email is only used as an in-memory/Redis key.
- With a remote storage the hit runs in the threadpool (a sync network call must not block the event loop). If the storage errors, the limiter fails open and logs.
- The old `RateLimiter` class and the `DEBUG`-based login skip were removed.
- Tests: `tests/unit/test_rate_limit.py` (no DB: `get_db` overridden, credential check and auth user lookup stubbed).

## Security notes

- Spoofing: without `TRUSTED_PROXY`, `X-Forwarded-For` is ignored (test). With it, only the proxy-appended entry counts; a client-prepended value does not change its bucket (test).
- Webhooks: 120/minute per connection is well above real Fathom/Tactiq delivery rates; limiting is per connection, so one noisy connection cannot starve another.

| 6 | Unauthenticated requests to protected routes share the per-IP default bucket (600/minute); a valid JWT gets its own per-user bucket. An attacker with a stolen valid token is limited per user, not per IP. | Accepted |
