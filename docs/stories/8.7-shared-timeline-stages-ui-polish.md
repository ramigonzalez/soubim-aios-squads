## Summary

Add stages support to the shared (public read-only) milestone timeline and polish several UI details across the milestone feature. The shared timeline API now returns stage data, the frontend maps shared data to component props with `preloadedStages`, and several UX improvements were made: star toggle excluded from export, `formatDate` hardened for edge cases, document upload button relocated to milestones toolbar, and today marker test updated for DOM-based positioning.

**User impact:** Shared milestone timeline links now show project stages (previously showed milestones without stage context), and several minor visual/functional issues resolved.

## Acceptance Criteria

### Backend — Shared Timeline Stages
- [x] `GET /api/shared-links/:token` response includes `stages` array
- [x] Stages include `stage_name`, `stage_from`, `stage_to` fields
- [x] Stages ordered chronologically

### Frontend — Shared Timeline Integration
- [x] `SharedMilestoneTimeline` page maps shared API response to `ProjectStage[]` type
- [x] `MilestoneTimeline` accepts `preloadedStages` prop (skips `useStages` hook when provided)
- [x] Shared view renders stages correctly with date ranges and "Current" highlighting
- [x] `useSharedLinks` hook updated with stages type mapping

### UI Polish
- [x] `MilestoneStarToggle` includes `data-export-exclude` attribute (hidden in PDF/JPEG exports)
- [x] `formatDate` utility hardened for null, ISO string, and invalid date inputs
- [x] Document upload button relocated from page header to milestones toolbar
- [x] `ProjectDetail` page layout cleaned up with button relocation

### Test Updates
- [x] `MilestoneTimeline.test.tsx` updated for DOM-based pixel positioning (mock `getBoundingClientRect` + `scrollHeight`)
