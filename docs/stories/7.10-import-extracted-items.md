# Story 7.10 — Import Pre-Extracted Items into a Meeting Source

**Story ID:** 7.10
**Epic:** E7 — Multi-Source Ingestion Pipeline
**Priority:** High | **Effort:** 1 SP
**Status:** Ready for Review
**Type:** Feature (dev tooling)
**Requested by:** Rami (first real meeting: souBIM + DIMAS, D/SEASON, 2026-09-04)

---

## Description

The first real meeting (D/SEASON quinzenal, 98 min) needs to enter the system, but meeting extraction inside the backend is currently broken (see Story 7.11). Extraction was run outside the backend instead: the production prompt (`app/prompts/extract_meeting.md`) rendered for the meeting and run through the Claude Code CLI on several models, to compare results without using API credits.

This story adds the missing link: a way to store that JSON output as ProjectItems linked to the meeting Source, keeping every field the prompt produces, and to mark the Source as processed.

**Out of scope:** UI for import, fixing the in-app extraction pipeline (Story 7.11), client/construtora entity.

## Acceptance Criteria

- [x] `import_items(db, source, items, approver_id, replace)` stores items as ProjectItems linked to the Source (`source_id`, `project_id`, `source_type`)
- [x] Items are validated with the same rules as in-app extraction (`extraction_v2._validate_item`); invalid items are skipped and counted
- [x] Decisions keep `why`, `causation`, `consensus`, `impacts`; all items keep the extracted `timestamp`
- [x] Action items keep `owner`, `due_date` (ISO, unparseable → null), `is_done`
- [x] Topic / idea / information context (`discussion_points` / `related_topic` / `reference_source`) is stored in `why`
- [x] Source is set to `processed`, `included=True`, `approved_at` set, `approved_by` set when an approver is given
- [x] Importing into a Source that already has items fails unless `--replace`
- [x] Only `meeting` and `manual_input` Sources can be imported into
- [x] CLI `scripts/import_extracted_items.py SOURCE_ID ITEMS_JSON [--approver EMAIL] [--replace] [--dry-run]`

### Added from review feedback (Rami, 2026-10-04, after seeing the D/SEASON items in the UI)
- [x] Extracted text must be in Portuguese — `extract_meeting.md` gets an "Output Language" rule: free text in the transcript's language, identifiers (keys, item types, disciplines, consensus status) stay in English
- [x] Page reload keeps the session — auth store restores the stored session at creation (it was restored in a `useEffect` after the first render, so `ProtectedRoute` redirected to `/login` first)
- [x] Item modal shows the meeting date (date only) and meeting title from the V2 source, not the import time; creation date/time only for items without a meeting
- [x] Items must read in meeting order — Project History groups V2 items under their Source (not only legacy `transcript_id`), dates them by `source.occurred_at` (not the import date), and orders items inside a meeting by `timestamp`
