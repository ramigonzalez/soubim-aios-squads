# Story 13.9 — Fathom Webhook (Push)

**Story ID:** 13.9
**Epic:** E13 — Recording Ingestion
**Priority:** Low | **Effort:** 5 SP (estimate)
**Status:** Draft
**Type:** Feature (integration)
**Requested by:** Rami — automate Fathom calls being sent to the platform

---

## Description

Optional automation after browse-and-pick (13.4) works: Fathom calls DecisionLog when a connected account's meeting is ready (`new_meeting` webhook), and the meeting lands in Ingestão as **pending** — never auto-imported into a project without a rule or a person choosing.

## Acceptance Criteria (draft)

- [ ] `POST /api/webhooks/fathom`: verify `webhook-id` / `webhook-timestamp` / `webhook-signature`, reject replays, idempotent per `webhook-id`
- [ ] Webhook registered per connection via the Fathom API when the user opts in
- [ ] Meeting → project mapping: rules per organization (e.g. calendar title contains "D/SEASON" → D/SEASON); unmatched meetings wait in an "Unassigned" list for a person to pick a project or discard
- [ ] Download via the `fathom_import` job (13.4)
- [ ] Opt-in per user; off by default (personal meetings would otherwise flow in)

## Dev Notes

- Requires a public HTTPS backend (13.8).
- Fathom webhook payload can include transcript, summary, action items (`include_transcript` etc.).
