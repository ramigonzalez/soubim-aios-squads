**Status:** Ready for Review

## Story

As **souBIM**, I want every LLM call to go through one OpenRouter key instead of a direct Anthropic key, so that billing and keys are in one place and the model can be changed by configuration.

## Context (current behaviour, verified)

- Every LLM call uses the Anthropic SDK with `ANTHROPIC_API_KEY`:
  - Meeting extraction: `app/services/extraction_v2.py` `_client()`, streamed, with the beta header `server-side-fallback-2026-07-01` and `extra_body` `output_config.effort` + `fallbacks`.
  - Documents: `app/api/routes/documents.py`, `app/services/document_extractor.py`.
  - Email: `app/services/email_extractor.py`, `app/services/gmail_poller.py`.
- The model name comes from `LLM_MODEL`. Costs are computed from `MODEL_PRICING` (13.6).
- Locally the key is a placeholder, so approving a meeting fails extraction.

  - Does the response report `usage` input and output tokens?

  - `OPENROUTER_BASE_URL` (default OpenRouter's).

- [x] Features that OpenRouter does not support (see the spike) are sent only when the provider is `anthropic`. Extraction still works without them.

## Spike results (2026-10-15, Rami's OpenRouter key, 9 tiny calls, < $0.01)

Anthropic SDK 0.79 with `base_url="https://openrouter.ai/api"` (the SDK appends `/v1/messages`).

| Question | Answer |
|---|---|
| Auth | Both work: `x-api-key` (SDK `api_key=`) and `Authorization: Bearer` (SDK `auth_token=`). The factory uses `api_key=`. |
| Streamed `messages` call | Accepted. `messages.stream(...)` + `get_final_message()` returns a normal `Message` (`stop_reason`, text blocks). |
| `anthropic-beta: server-side-fallback-2026-07-01` | Accepted silently (no error); no way to tell whether it is honoured. Useless without `fallbacks`, so not sent to OpenRouter. |
| `extra_body.output_config.effort` | Accepted and validated by OpenRouter (an invalid value returns 400 listing `low/medium/high/xhigh/max`), so it is understood. Sent on both providers. |
| `extra_body.fallbacks: "default"` | **Rejected, 400** `fallbacks: expected array, received string` — OpenRouter treats `fallbacks` as its own (routing) field. Sent only to the Anthropic provider. |
| `usage` | Reported: `input_tokens` / `output_tokens` on create and stream. |
| Model id | `anthropic/claude-opus-5.5` is the canonical id (returned in `message.model`). `anthropic/claude-opus-5-5` is also accepted and resolves to it. Use **`LLM_MODEL=anthropic/claude-opus-5.5`**. |

The Anthropic-compatible endpoint is usable, so the OpenAI-compatible endpoint (Decision Q1) was not needed; no new dependency.
End-to-end check: `run_meeting_extraction` through the factory with `LLM_PROVIDER=openrouter` returned parsed items, usage (75 in / 54 out) and a cost of $0.00138 mapped to the `claude-opus-5-5` price.

## Implementation notes

- `app/services/llm_client.py`: `get_llm_client()` (Anthropic SDK; OpenRouter = same SDK with `OPENROUTER_BASE_URL`), `supports_server_side_fallback()`, `check_provider_key()`, `pricing_key()` / `lookup_pricing()`.
- Settings: `LLM_PROVIDER` (`anthropic` default, case-insensitive), `ANTHROPIC_API_KEY` now optional, `OPENROUTER_API_KEY`, `OPENROUTER_BASE_URL` (default `https://openrouter.ai/api`). A model validator fails startup (API and worker both import `settings`) with `LLM_PROVIDER=<p> needs <KEY>, which is not set`; blank keys count as missing. `hide_input_in_errors` keeps setting values (secrets) out of that startup error.
- Extraction (`extraction_v2._stream_options`): Anthropic sends beta header + `effort` + `fallbacks`; OpenRouter sends `effort` only.
- Cost: `anthropic/claude-opus-5.5` → `claude-opus-5-5` (strip `anthropic/`, `.` → `-`). Unknown models → no cost; the versions list now shows "custo desconhecido" when tokens are known but there is no price.

## Assumptions & gaps

- The server-side refusal fallback is lost on OpenRouter: a refusal now fails the extraction with the existing "The model declined…" error instead of being retried on a fallback model. Accepted for phase 1 (OpenRouter's own fallback options are out of scope).
- Whether OpenRouter really applies `effort` upstream could not be measured with tiny prompts; it is accepted and validated, and extraction works.
- `anthropic-beta` header behaviour on OpenRouter is unknown (silently accepted); we simply don't send it there.
- `summary_service.py` (Tactiq webhook summaries) was a sixth call site not listed in the story; it uses the factory too.
- `ExtractionRun.model` stores what the provider returns: OpenRouter runs show `anthropic/claude-opus-5.5` in the versions list.
- The cost mapping only knows Claude ids (`anthropic/` prefix); non-Claude models show "custo desconhecido" (phase 2, with 13.14).
- Not verified on Railway: the variables must be set on both `api` and `worker` and both redeployed.
- `.env.example` (legacy, non-development) was not changed; `.env.development.example` is the documented template.

## Out of scope (phase 2)

- Using non-Claude models through OpenRouter (needs the eval of 13.14 first).
- OpenRouter's own routing or fallback options.

## Open questions

1. If the spike shows that OpenRouter's Anthropic-compatible endpoint drops something important, is the OpenAI-compatible endpoint acceptable? That needs more code. — **Rami/@architect**
2. Keep the direct Anthropic provider as an option (proposed yes, it costs nothing), or remove it? — **Rami**

## Decisions (Rami, 2026-10-09)

- Q1 yes: if the Anthropic-compatible endpoint drops something important, the OpenAI-compatible endpoint is acceptable. Q2 yes: keep the direct Anthropic provider as an option.
- Rami added `OPENROUTER_API_KEY` to the local `.env.development`; `Settings` forbids unknown keys, so the setting must be declared before the backend/worker restart (it fails to start until then).
