## Story

As **souBIM**, I want every LLM call to go through one OpenRouter key instead of a direct Anthropic key, so that billing and keys are in one place and the model can be changed by configuration.

## Context (current behaviour, verified)

- Every LLM call uses the Anthropic SDK with `ANTHROPIC_API_KEY`:
  - Meeting extraction: `app/services/extraction_v2.py` `_client()`, streamed, with the beta header `server-side-fallback-2026-07-01` and `extra_body` `output_config.effort` + `fallbacks`.
  - Documents: `app/api/routes/documents.py`, `app/services/document_extractor.py`.
  - Email: `app/services/email_extractor.py`, `app/services/gmail_poller.py`.
- The model name comes from `LLM_MODEL`. Costs are computed from `MODEL_PRICING` (13.6).
- Locally the key is a placeholder, so approving a meeting fails extraction.

## Acceptance Criteria (draft)

- [ ] **Spike first (no spend beyond a few cents, Rami's key):**
  - Does OpenRouter's Anthropic-compatible endpoint (Anthropic SDK with `base_url` set to OpenRouter) accept our streamed call?
  - What happens to the extra fields: the `anthropic-beta` fallback header, `output_config.effort` and `fallbacks`?
  - Does the response report `usage` input and output tokens?
  - Record the answers here.
- [ ] One client factory (`app/services/llm_client.py`) used by all five call sites. It is configured by:
  - `LLM_PROVIDER` = `anthropic` | `openrouter` (default `anthropic`, so nothing changes until it is set).
  - `OPENROUTER_API_KEY`.
  - `OPENROUTER_BASE_URL` (default OpenRouter's).
- [ ] `LLM_MODEL` accepts the OpenRouter model id (e.g. `anthropic/claude-opus-5-5`). The cost display maps that id to the same `MODEL_PRICING` entry, or shows "custo desconhecido".
- [ ] Features that OpenRouter does not support (see the spike) are sent only when the provider is `anthropic`. Extraction still works without them.
- [ ] `ANTHROPIC_API_KEY` is no longer required when the provider is `openrouter`. Startup fails with a clear message when the chosen provider has no key.
- [ ] Tests:
  - Fake client for both providers.
  - The factory picks the right one.
  - The provider-only fields are dropped for OpenRouter.
  - The missing-key error.
- [ ] Docs: `.env.development.example`, `DEPLOYMENT_RAILWAY.md` (variables on the API **and** worker services).

## Out of scope (phase 2)

- Using non-Claude models through OpenRouter (needs the eval of 13.14 first).
- OpenRouter's own routing or fallback options.
