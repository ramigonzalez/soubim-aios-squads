# Story 12.6 — Item Review: Approve / Reject / Edit by Role

**Story ID:** 12.6
**Epic:** E12 — Organizations & Client Access
**Priority:** Medium | **Effort:** 5 SP (estimate)
**Status:** Draft
**Type:** Feature
**Requested by:** Rami — "approve/reject project items, maybe edit them too, only restricted persons"

---

## Description

Extracted items go straight into Project History today. Reviewers should be able to **approve, reject or edit** each item; edits keep the AI's original so corrections can be compared. Only users with a reviewer-capable role in the owning organization can review.

## Acceptance Criteria (draft)

- [ ] Item `review_status` (`pending` / `approved` / `rejected`), `reviewed_by`, `reviewed_at`
- [ ] Edit title / statement / why / owner / due date; the original extracted values are kept (e.g. `original` JSON) and viewable
- [ ] Only owner-organization `admin`/`owner` (or a `reviewer` role if added in 12.1) can review
- [ ] Bulk approve / reject from Project History
- [ ] Rejected items hidden from History by default (filter to show)

## Dev Notes

- Open decision (with Youval): do non-reviewers and shared organizations see `pending` items (with a badge) or only `approved` ones?
- Interplay with extraction versions (13.7): reviews belong to a version; switching versions shows that version's review state. Carrying reviews across versions is out of scope (matching "the same item" across runs is fuzzy).
