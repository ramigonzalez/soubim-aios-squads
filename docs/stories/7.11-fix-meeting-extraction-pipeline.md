## Problem Statement

Approving a `meeting` or `manual_input` Source never produces items. Found while preparing the first real meeting (Story 7.10 imported it out-of-band instead):

1. **Crash before the LLM call.** `ingestion_pipeline.py:73-83` calls `extract_items_from_transcript(..., project_id=..., source_id=...)`; the function (`extraction_v2.py:75-83`) has no such parameters → `TypeError` → Source marked `failed`. Retry repeats the error.
2. **Model may be retired.** `extraction_v2.py`, `summary_service.py`, `email_extractor.py`, `document_extractor.py`, `documents.py` hardcode `claude-sonnet-4-20250514`. Calling it via the Claude Code CLI on 2026-10-04 returned 404 ("may not exist or you may not have access"). Not yet confirmed against the API.
3. **Output cut off.** `max_tokens=4096`. For the 98-min D/SEASON meeting, every model tested produced more (Sonnet 5.5 ≈ 4.1k, Haiku 4.5 ≈ 11.6k, Opus 5.5 ≈ 11.3k output tokens incl. thinking) → truncated JSON → parse error → `[]`.
4. **Meeting context not passed.** Title, date, type, duration are not sent, so the prompt says "Untitled Meeting", 0 minutes. `role` is not passed in the roster.
5. **Fields lost when storing.** `why` read from `item_data["context"]` (always "Extracted from source"); `consensus` forced to `{}`; `causation`, `impacts`, `due_date` dropped; `timestamp` overwritten with `source.occurred_at`.
6. **Timestamp format ambiguity.** Transcripts use `m:ss` under one hour and `h:mm:ss` after; the prompt asks for `HH:MM:SS`. In the D/SEASON run one model returned `1:20:05` for an item another placed at `20:05`.
7. **Uncertain speakers.** Re-transcribed meetings mark uncertain speakers as `⚠️ Camila / Erica [reason]`. The prompt does not say how to treat them (should attribute to the group, not pick one).

- [x] Test: truncated output, invalid JSON, missing items, refusal and empty transcript fail the source with a readable `extraction_error` (no more silent "0 items")

## Dev Notes

- Model comparison for the D/SEASON meeting: `data/eval/dseason-2026-09-04/comparison.md` (local). Opus 5.5 gave the most complete output (46 items, all decisions with why + consensus + impacts); Sonnet 5.5 was fastest (28 s) but only 1/5 decisions had all fields.
- **Default model:** `claude-opus-5-5` (most complete in the D/SEASON eval; Anthropic's guidance defaults to Opus). Sonnet 5.5 (cheaper, faster, also complete in the latest eval) is `LLM_MODEL=claude-sonnet-5-5` — decide with Youval.
- **Refusal fallback** opted in by default: header `anthropic-beta: server-side-fallback-2026-07-01` + `fallbacks: "default"` (via `extra_body`, as are `output_config.effort` — SDK 0.79 has no typed parameters for them). **Not yet run against the live API** (tests use a fake client; a real run costs ~$0.30 on Opus for a 98-min meeting and the dev key should be rotated first) — the first real run confirms these two fields; drop them if the API rejects them.
- Email / document extractors keep their own item mapping (out of scope); only their model id changed. Their `max_tokens=4096` with an always-thinking model may truncate long documents — follow-up.
- Pre-existing ruff findings in `app/config.py` imports are untouched.
