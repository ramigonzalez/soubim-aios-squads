# Story 7.9 — Ingestion Workflow Redesign: Unified Status & History

**Epic:** 7 (Ingestion Pipeline)
**Priority:** Highest | **Effort:** 5 SP (~2 days)
**Status:** In Progress
**Type:** Refactor + Feature

## Description

The current ingestion pipeline has two disconnected flags — `included` (Boolean toggle) and `ingestion_status` (enum). This creates contradictory states (`included=true` + `rejected`, `included=false` + `approved`) and a toggle that serves no functional purpose (the pipeline never checks `included`). Additionally, when extraction fails after approval, the source stays stuck at `approved` with no error feedback, no retry, and no `failed` status.

This story redesigns the ingestion workflow into a single coherent state machine, adds a historical view of processed/rejected/failed sources, and provides cascade delete to remove a source along with all its extracted ProjectItems and embeddings.

### Current Problems

1. **`included` is decorative** — `process_approved_source()` at `ingestion_pipeline.py:33` only checks `ingestion_status != "approved"`, never checks `included`
2. **Contradictory states** — Nothing prevents `included=true + rejected` or `included=false + approved`
3. **Silent extraction failures** — Exception at `ingestion_pipeline.py:109-111` catches error, logs it, rolls back DB, but source stays `approved` forever
4. **No `failed` status** — CHECK constraint only allows: `pending`, `approved`, `rejected`, `processed`
5. **No history view** — Once sources are processed/rejected, they disappear from the default pending filter with no way to review them
6. **No audit trail** — No way to see who approved/rejected, when, or what was extracted
7. **No cascade delete** — If a bad source was processed, there's no way to remove its extracted items + embeddings

### Target State Machine

```
pending → approved (included auto-set to true)
                  → processed ✅ (extraction succeeded)
                  → failed ⚠️ (extraction error — retryable)
       → rejected (included auto-set to false) ❌
```

## Acceptance Criteria

- [ ] `included` becomes **read-only** in the UI — auto-set by approve (`true`) / reject (`false`)
- [ ] New `failed` status added to `ingestion_status` enum (DB CHECK constraint + frontend types + badge)
- [ ] Pipeline sets `ingestion_status = 'failed'` on extraction error instead of silently staying `approved`
- [ ] Retry button available for `failed` sources (re-triggers `process_approved_source`)
- [ ] Include toggle removed from row components — replaced with read-only indicator
- [ ] **History tab/section** showing processed, rejected, and failed sources
- [ ] History shows: source info, status, approved/rejected by (user name), approved/rejected at (timestamp), item count extracted
- [ ] **Cascade delete endpoint**: DELETE `/ingestion/{source_id}` removes source + all linked ProjectItems + their embeddings
- [ ] Cascade delete button in history view with confirmation dialog
- [ ] Pipeline checks `source.included == True` as defense-in-depth before processing

## Dev Notes

### Backend Changes

**A. Database Model (`models.py`)**
- Update CHECK constraint: add `'failed'` to allowed `ingestion_status` values
- Add `rejected_by` (GUID FK to users) and `rejected_at` (DateTime) columns to Source
- Migration: `ALTER TABLE sources DROP CONSTRAINT ck_ingestion_status_valid; ALTER TABLE sources ADD CONSTRAINT ck_ingestion_status_valid CHECK (ingestion_status IN ('pending', 'approved', 'rejected', 'processed', 'failed'));`
- Add columns: `ALTER TABLE sources ADD COLUMN rejected_by UUID REFERENCES users(id); ALTER TABLE sources ADD COLUMN rejected_at TIMESTAMP;`

**B. Ingestion Pipeline (`ingestion_pipeline.py`)**
- In `process_approved_source()`: add `if not source.included:` guard after status check (defense-in-depth)
- In exception handler: set `source.ingestion_status = 'failed'` and commit (don't leave at `approved`)
- Store error message: add `extraction_error` Text column to Source (optional, for debugging)

**C. Ingestion Routes (`ingestion.py`)**
- On approve: auto-set `source.included = True`
- On reject: auto-set `source.included = False`, set `rejected_by` and `rejected_at`
- Remove standalone `included` toggle from PATCH (no longer independently settable)
- Add `GET /ingestion/history` endpoint: returns processed/rejected/failed sources with approval metadata and extracted item count
- Add `DELETE /ingestion/{source_id}` endpoint: cascade delete source → ProjectItems (via `source_id` FK) → embeddings (column on ProjectItem)
- Add retry endpoint: `POST /ingestion/{source_id}/retry` — resets `failed` → `approved`, re-triggers pipeline

**D. Pydantic Models**
- Update `SourceUpdate` to remove `included` field (no longer PATCH-able)
- Add `SourceHistoryResponse` with approval metadata and item count
- Update `IngestionStatus` literal to include `'failed'`

### Frontend Changes

**E. Types (`ingestion.ts`)**
- Add `'failed'` to `IngestionStatus` type
- Add `approved_by_name`, `approved_at`, `rejected_by_name`, `rejected_at`, `extracted_item_count` to `BaseSource`

**F. Status Badge (`IngestionStatusBadge.tsx`)**
- Add `failed` style: orange/amber background with warning icon

**G. Row Components (`MeetingSourceRow.tsx`, `EmailSourceRow.tsx`, `DocumentSourceRow.tsx`)**
- Remove include toggle button — replace with read-only indicator (checkmark icon if included, dash if not)
- Add retry button for `failed` status rows
- Keep approve/reject buttons for `pending` rows

**H. IngestionApproval Page (`IngestionApproval.tsx`)**
- Add tab system: "Pending" (default) | "History" (processed + rejected + failed)
- History tab shows: source info, status badge, approved/rejected by, timestamp, item count, delete button
- Delete button opens confirmation dialog: "This will permanently delete X extracted items and their embeddings. Continue?"
- Remove include toggle column header, replace with "Included" read-only column

**I. Service & Hooks**
- `ingestionService.ts`: add `getHistory()`, `deleteSource()`, `retrySource()` methods
- `useIngestionMutation.ts`: add `useDeleteSource()`, `useRetrySource()` hooks
- `useIngestion.ts`: add `useIngestionHistory()` hook
- Remove `useToggleInclude` hook (no longer needed)

## Verification

1. **Approve flow**: Click approve on pending source → `included` auto-sets to `true` → extraction runs → status becomes `processed`
2. **Reject flow**: Click reject on pending source → `included` auto-sets to `false` → source appears in History tab as rejected
3. **Failed flow**: Simulate extraction error → source shows `failed` status with amber badge → click retry → re-processes
4. **History tab**: Shows all processed/rejected/failed sources with who approved/rejected, when, and item count
5. **Cascade delete**: In history, click delete on processed source → confirmation → source + all extracted items + embeddings removed
6. **No contradictory states**: Cannot have `included=true + rejected` or `included=false + approved`
