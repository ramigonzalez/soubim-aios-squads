# Story 14.1 — GPU Transcription Job (Modal)

**Story ID:** 14.1
**Epic:** E14 — Speaker Review & GPU Transcription
**Priority:** Medium | **Effort:** 8 SP (estimate)
**Status:** Draft
**Type:** Feature (data pipeline)
**Requested by:** Rami — "SPEAKERS audit … can we include this in the platform itself?"

---

## Description

Move the local re-transcription pipeline (`data/tools/transcription/`: WhisperX large-v3 + pyannote speaker-diarization-community-1 + voiceprints) to a **serverless GPU function** (Modal) called by a `transcribe` job (13.2). It reads the recording from storage through a signed link and writes back words with timestamps, detected voices (turns) and per-voice audio clips for review (14.2).

## Acceptance Criteria (draft)

- [ ] **First task — measure:** run D/SEASON (98 min) on an L4 GPU; record wall time and cost; go/no-go with Youval (target ≤ $0.20/meeting)
- [ ] Modal function: input signed recording URL + language (`pt`), output ASR JSON (word timestamps), diarization turns, 3 clips per voice (stored in storage)
- [ ] `transcribe` job handler: call the function, save outputs, move the meeting to "awaiting speaker review"
- [ ] Hugging Face token (pyannote model terms accepted) and Modal token as secrets
- [ ] Failure/timeout handling with retry; cost per run logged

## Dev Notes

- Local reference (M3 CPU, 98 min): ASR ~80 min, diarization ~1.5 min (MPS). GPU estimate 5–10 min ≈ $0.10–0.15 on Modal L4 ($0.80/h, per-second billing, scales to zero) vs ~$1–1.30 on Railway CPU (no GPUs) — estimates, not measured.
- Pilot quality (D/SEASON): remote speakers separated reliably; people sharing one room mic could not be separated by voiceprint → mixed-voice clusters marked ⚠️ (`Camila / Erica`).
- Scripts to port: `run_whisperx_asr.py`, `diarize_only.py`, `cut_speaker_clips.py`, `voiceprint.py`.
