# Story 12.4 — Meeting Visibility: Internal vs Shared

**Story ID:** 12.4
**Epic:** E12 — Organizations & Client Access
**Priority:** High | **Effort:** 5 SP (estimate)
**Status:** Ready for Review
**Type:** Feature (security)
**Requested by:** Rami — "souBIM can have their own internal meetings, other clients' meetings. As well as DIMAS. Also they can have their own shared meetings"

---

## Description

On a shared project, each organization still has meetings the others must not see (souBIM internal design reviews, DIMAS internal site meetings). Every meeting (Source) gets an **owner organization** and a **visibility**: `internal` (owner organization only) or `shared` (all organizations on the project). Extracted items follow their meeting's visibility.

## Acceptance Criteria

- [x] `sources.owner_organization_id` and `sources.visibility` (`internal` | `shared`), default `internal`; backfill existing sources to the project owner org, `internal` (migration `013_story_12_4`, after 13.4's `011_story_13_4` and 12.5's `012_story_12_5`)
- [x] Items of a source inherit its visibility (no separate per-item visibility in this story) — read from the source on every request, so a switch applies immediately
- [x] Project History, milestones, digest, search, ingestion, meeting viewer and recording links show only meetings visible to the user's organization (see Route coverage)
- [x] The owner organization can change a meeting from internal to shared (and back), with confirmation — `PATCH /api/sources/{id}/visibility`, owner/admin of the meeting's organization; inline confirmation in the meeting viewer
- [x] Badge in the meeting header and viewer: "Interna" / "Compartilhada" (History source-group header + meeting viewer)
- [x] Isolation tests: a viewer organization never sees internal meetings or their items/recordings (`tests/unit/test_meeting_visibility.py`, viewer **and** contributor)

## Dev Notes

- Meetings imported from a user's Fathom (13.4) are owned by the importing user's active organization and start `internal`; the importer chooses to share.
- Manual items without a source (`manual_input`) need a rule — proposal: owned by the creating user's organization, `internal` unless shared.
- Milestones and shared timeline links (Story 8.x) must not leak internal items.

## Visibility rules (implemented)

All in `app/services/access.py` (extends the 12.2/12.3 rules):

| Object | Visible to |
|--------|------------|
| Source `shared` | everyone who can read the project (12.2/12.3 level ≥ `read`) |
| Source `internal` | users who reach the project **through the source's owner organization** (owner/admin of it, or an assigned member — same rule as project access) |
| Item with a source | same as its source |
| Item without a source (manual input) | users who reach the project through the item's owner organization (`project_items.owner_organization_id`) — always internal |
| Public share link (`/api/shared/milestones/{token}`, anonymous) | only items of `shared` sources |

| Owner of a new… | Rule |
|-----------------|------|
| Source from a user (Tactiq webhook, document upload) / manual item | the user's **acting organization** on the project: the owning organization if they reach the project through it, otherwise the shared organization giving the highest level (`acting_organization_id`) |
| Meeting imported from Fathom (13.4) | the importer's acting organization on the project, stored on the `fathom_imports` row at import time with the chosen visibility (`internal` default; `shared` only for owner/admin of that organization — `can_create_shared`); the worker copies both onto the Source |
| Source from platform ingestion (Gmail, Drive, seed, any path that does not set it) | the project's owning organization (SQLAlchemy `before_flush` default in `models.py`) |

Who can change visibility: owner/admin of the source's owner organization who reaches the project through it (`can_change_visibility`; exposed as `can_change_visibility` in the meeting viewer response). Everyone else: 403 if they can see the meeting, 404 if not.

Helpers: `project_access_by_organization` (level per organization; `project_access_level` = max), `visible_sources_filter` / `visible_items_filter` (SQL, for lists and counts), `source_visible` / `item_visible` (single objects), `public_items_filter`, `can_change_visibility`, `acting_organization_id`. `require_source_access` now also answers 404 for another organization's internal source, so every source route (meeting viewer, recording link, curation, ingestion mutations) inherits the rule.

## Assumptions & gaps

Each item: chosen option — alternatives — who should confirm.

1. **Backfill: existing sources → project owner org, `internal`** (story AC, and the safe default). The owner organization sees exactly what it saw before; organizations a project was shared with in 12.3 stop seeing existing meetings until the owner shares them. — Alt: backfill `shared` (keeps 12.3 shared orgs' current view, but leaks every historical internal review). — **Rami**.
2. **Manual items (no source) are internal to the creator's organization**, with no way to share them (AC: no per-item visibility). Stored in `project_items.owner_organization_id` (nullable; only read when `source_id` is NULL; backfilled to the project owner). — Alt: a per-item `visibility` column / wrap manual items in a `manual_input` source so they can be shared. — **Rami / @po** (12.6 or later).
3. **Who can change visibility: owner/admin of the meeting's organization** (reaching the project through it). Not the uploader: sources have no `created_by` today. Fathom import (13.4): the importer chooses internal/shared in the dialog, but only owner/admin of their organization may pick `shared` (same rule as the switch; members import `internal`). Owner-org members cannot change it. — Alt: any user with write access in the owner organization. — **Rami**.
4. **Acting organization** for user-created sources/items/Fathom imports = the project's owning organization if the user reaches the project through it, else the shared organization with the highest level. 12.5 merged an active organization (`X-Organization-Id`, today only narrowing `GET /api/projects`); it could later choose the owning organization for users in several organizations on the same project — not wired in 12.4 (kept out of scope on purpose). — **Rami**.
5. **Public milestone share links show only milestones of `shared` meetings** (Dev Note "must not leak internal items"). With the internal backfill, **existing public links show no milestones until the owner shares the meetings** — a visible change for current links. — Alt: show what the link creator's organization sees (would publish internal items on a public URL). — **Rami** (confirm before deploy).
6. **Approval stays with the project owner's admins (12.2/12.3)**. Consequence: a contributor organization's *internal* pending meeting (Tactiq webhook / document upload by its users) is invisible to the project owner, so nobody can approve it until the contributor shares it; the contributor sees it in its queue but gets 403 on approve. — Alt: let owner/admins of the source's organization approve their own sources (ETL cost on the platform, items visible only to them). — **Rami** (needed before 13.4 imports go live).
7. **Shared pending sources are visible to shared organizations** in the ingestion queue (read-only; mutations remain owner-admin). — Alt: limit the pending queue to users who can act on it. — **@po**.
8. **Recording storage key** still uses the project owner's organization (`org_id_for_source`, 13.1); unchanged because existing recordings live there. 13.4/13.9 may move to `sources.owner_organization_id`. — **@architect**.
9. **Gap — digest** is a stub (returns zeros); when implemented it must filter with `visible_items_filter`.
10. **Gap — ingestion page / project History** show the badge only in the History source-group header and meeting viewer (story scope); the ingestion list returns `visibility` but the Ingestion UI does not render it yet.
11. **Gap — review**: @po review per epic table; @architect review of `access.py` changes recommended (security-critical, same as 12.2).

## Security review

Reviewed `git diff origin/main...HEAD` after rebasing onto main with 13.4 (Fathom import) and 12.5 (invitations, active organization). Migration renumbered to `013_story_12_4` (down_revision `012_story_12_5`).

**Route coverage — confirmed independently.** Every router in `app/main.py` (18 routers, all handlers in `app/api/routes/*.py`) was enumerated again. Every handler that returns or mutates sources/items goes through `visible_items_filter` / `visible_sources_filter` (lists, facets, search, milestones, counts, project cards and stats, V1 list and facets, ingestion list/history/count/pending_count) or `item_visible` / `source_visible` / `require_source_access` (item and V1 detail/patch, meeting viewer incl. local signed link and storage presign, visibility switch, curation status, upload-to-storage, ingestion approve/reject/retry/delete/batch, webhook duplicate). Public share links use `public_items_filter`. Item responses embed `source` only for items that passed the filter, and an item's visibility *is* its source's, so the embedded `source` never leaks. No "related"/"similar" endpoint exists; `similar_decisions`/`consistency_notes` (V1 detail) are never populated. Participants, stages, organizations, members/invitations (12.5), project sharing, auth, health and admin expose no source/item data. 12.5's `X-Organization-Id` only narrows `GET /api/projects` and does not affect these checks (not extended here). Shared-organization users cannot change visibility of another organization's meeting (`can_change_visibility` requires owner/admin of the meeting's organization) and cannot mint share links (project `admin` only, owner organization), and links show shared meetings only.
