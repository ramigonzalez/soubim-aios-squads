## Summary

Fix auth middleware to return `JSONResponse` instead of raising `HTTPException`. FastAPI middleware cannot use `raise HTTPException` — the exception propagates outside the middleware stack and results in unhandled 500 errors instead of proper 401/403 responses. All error paths now return `JSONResponse` directly with matching status codes and `WWW-Authenticate` headers.

**User impact:** Unauthenticated requests returned 500 Internal Server Error instead of proper 401 Unauthorized with helpful error messages.

---

## Acceptance Criteria

- [x] All auth error paths in middleware return `JSONResponse` instead of raising `HTTPException`
- [x] Response status codes match original intent (401, 403)
- [x] `WWW-Authenticate: Bearer` header included in 401 responses
- [x] Error response body includes descriptive `detail` message
- [x] Authenticated requests continue to work normally (no regression)

---

## Root Cause

FastAPI's `BaseHTTPMiddleware` processes requests outside the normal exception handler chain. When middleware raises `HTTPException`, it bypasses FastAPI's built-in exception handlers and surfaces as an unhandled exception (500). The correct pattern is to return a `JSONResponse` directly from middleware.
