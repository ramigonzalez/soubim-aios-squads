# Story 11.1 — Interface in Brazilian Portuguese (i18n)

**Story ID:** 11.1
**Epic:** E11 — Localization (Brazilian AEC market)
**Priority:** High | **Effort:** 5 SP
**Status:** Ready for Review
**Type:** Feature
**Requested by:** Rami — "we will start chasing Brazilian AEC companies"

---

## Description

All interface labels move to Brazilian Portuguese, using `i18next` + `react-i18next`. Portuguese is the default; English stays as fallback (and as the language the existing tests assert). Code, identifiers, API values and user data stay as they are.

**Out of scope:** a language switcher in the UI (one line with `i18n.changeLanguage` when needed), backend/API error messages (shown as received), the date picker's calendar month names (needs `registerLocale` with `date-fns/locale/pt-BR`), user data (project/stage/meeting names, transcripts, extracted items — those follow the extraction prompt's language rule from Story 7.10).

## Acceptance Criteria

- [x] `src/i18n/index.ts`: i18next initialized with `pt-BR` default, `en` fallback; namespaces auto-loaded from `src/i18n/locales/<lang>/<namespace>.json`
- [x] Every user-visible string (text, headings, buttons, placeholders, aria-labels, titles, empty/error/loading states, confirmations, validation messages, export text) comes from translations — 54 components/pages
- [x] Shared labels (disciplines, item types, source types) and dates (`formatDate`, `formatDateTime`, `formatDenseDate`, `formatFullDate`, hardcoded `'en-US'` dates) follow the current language: "4 de set. de 2026", "4 SET 2026"
- [x] Counts use plural rules (`_one` / `_other`): "1 item" / "28 itens"
- [x] One glossary across the app (e.g. Rationale → Justificativa, Causation → Origem, Milestone → Marco, action item → Ação, Executive Digest → Resumo executivo, Ingestion → Ingestão)
- [x] Tests run in English (`src/tests/setup.ts`); English strings are unchanged so existing tests still pass
- [x] Translation safety tests: every namespace exists in both languages with identical keys and no empty values; Portuguese rendering of shared labels, dates and the item modal

## Dev Notes

- **Kept as-is:** discipline initials (A, Cl, E…) — colour-coded visual codes; translating them would create clashes (Estrutura/Elétrica). `DisciplinePill` abbreviations ("Arch", "Struct") come from `abbreviateDiscipline` and stay English for now.
- **Small English changes** (no test asserted the old text): singular forms where the old code always pluralized ("1 turn", "1 participant", "1 extracted item"); a few screen-reader labels now use readable names ("Source: Meeting", "MEP" instead of "Mep"); the consensus list shows translated discipline names.
- Adding a string: add the key to both `pt-BR/<ns>.json` and `en/<ns>.json` — the parity test fails otherwise.
- No new type errors (7 pre-existing before → 5 now; 2 unused-variable errors disappeared). ESLint: 0 errors.
