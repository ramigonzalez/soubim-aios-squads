# Story 13.5 — Manual Upload: .mp4 and .txt

**Story ID:** 13.5
**Epic:** E13 — Recording Ingestion
**Priority:** High | **Effort:** 5 SP (estimate)
**Status:** Ready for Review
**Type:** Feature
**Requested by:** Rami — "provide a way to import recordings .mp4 manually … also .txt files"

---

## Description

Meetings outside Fathom (Teams, in-person, phone, other recorders) are uploaded by hand: a **video** (.mp4) and/or a **transcript** (.txt). Large videos go **directly from the browser to storage** (pre-signed multipart), never through the API server.

## Acceptance Criteria

- [x] "Adicionar reunião" form (button in Ingestão): project, title, date, visibility (internal default / shared), participants; video file and/or transcript file
- [x] Video: pre-signed upload straight to storage (13.1) with progress; size limit from settings (`RECORDING_MAX_BYTES`); extension/content-type check — **single signed PUT, not multipart/resume** (see Assumptions)
- [x] Transcript .txt: Fathom format (`M:SS - Name` + indented speech) parsed as today (`lib/transcript.ts`); **plain-text mode** for text without timestamps — the viewer shows the text without turn links. Items without timestamp links: nothing to change in this story (see Assumptions)
- [x] Creates a pending Source in Ingestão; extraction starts on approval as today (13.6 is the worker move of that same step)
- [x] Supersedes the manual-paste idea of Story 7.8 — 7.8 marked as superseded

## Implementation

```
Dialog ──POST /uploads/presign {project_id, filename, size}──▶ API: write access, storage on, extension, size
       ◀── {source_id, upload_url (signed PUT, Content-Type signed), headers} ──
Browser ──PUT video──▶ storage  (org/<project org>/sources/<source_id>/recording.<ext>; progress bar)
Dialog ──POST /uploads/complete {project_id, title, occurred_at, participants, transcript?, source_id?, video_extension?}──▶
        API: write access; HEAD the object (exists, 0 < size <= max) → Source(meeting, pending, included=false, label "Upload")
Transcript-only: only /complete, no storage needed.
```

- Backend: `app/api/routes/uploads.py` (`GET /api/uploads/projects`, `POST /api/uploads/presign`, `POST /api/uploads/complete`), `app/services/manual_upload.py`, `storage.presigned_put`. No migration: the Source id is pre-allocated by `presign` and used as the storage key; nothing is persisted until `complete`.
- Errors: 503 storage not configured (video only), 415 extension, 413 too large (presign, and at complete for an object over the limit — it is deleted), 422 empty file / nothing to upload / bad id, 404 object not in storage, 409 already completed, 403/404 no write access (12.2 `require_project_access`).
- Frontend: `AddMeetingDialog` (organism) opened from the Ingestão header; `lib/upload.ts` (validation, UTF-8 with Windows-1252 fallback decoding), `services/uploadService.ts` (bare axios PUT: no API Bearer on the storage request); `MeetingViewer` plain-text mode when the transcript has no `M:SS - Name` turns.
- Nothing is extracted on upload; the meeting waits for approval like every other source.

## Assumptions & gaps

Each item: chosen option — alternatives — who should confirm.

1. **Single signed PUT, no multipart / resume** — the plan default limit is 2 GB (< 5 GB S3 single-PUT cap), so one presigned PUT covers it, with progress via XHR. A failed upload restarts from zero ("Try again"). Alternative: S3 multipart presign (part URLs + complete/abort) for resume and > 5 GB. — **Rami** (needed if recordings above 2 GB or flaky links matter).
2. **Done (12.4 integrated)** — `complete` takes `visibility` (`internal` default | `shared`), sets `sources.owner_organization_id` with `acting_organization_id` (same helper as the Fathom import) and 403s `shared` unless `can_create_shared` (owner/admin of the organization the user acts for). Checked at `complete`, i.e. at the moment the Source is created, so it needs no binding in the upload token. `GET /api/uploads/projects` returns `can_share`; the dialog offers Internal / Shared, Shared disabled with a hint when `can_share` is false.
3. **Storage required only for video** — video upload returns 503 when `S3_*` is not set (no local-disk fallback, consistent with 13.4); transcript-only works without storage. Alternative: local `uploads/recordings` fallback. — **Rami**.
4. **Entry point = button in Ingestão** (directors only, like the page); project picker lists projects with write access (reuses the 13.4 rule). Alternative: also a button on the project page. — **UX/Rami**.
5. **Transcript decoded in the browser** and sent as JSON text (limit 2 MB / 2,000,000 chars). UTF-8 first, Windows-1252 fallback (Latin-1 superset). Server stores what it receives. Alternative: upload the .txt to the API as multipart and detect the encoding server-side. — **@architect**.
6. **Fixed — upload ids are signed** — `presign` returns an `upload_token` (HMAC-SHA256 with a key derived from `JWT_SECRET_KEY`) over source id, project id, user id, storage key (so also the extension) and a 6 h expiry; `complete` recomputes it with a constant-time compare and answers 403 when it is missing, tampered, expired, or used by another user / for another project / another id or extension. Transcript-only uploads have no pre-allocated id, so no token.
7. **Orphan objects** — a video uploaded but never completed (tab closed) stays in the bucket under an unused id; the bucket lifecycle rule (13.1) expires it. No cleanup job. — **Rami**.
8. **Video without transcript is allowed** (story Dev Notes: wait for E14 or add one); approving it runs extraction on empty text. Alternative: block approval until a transcript exists. — **@po**.
9. **Date field** is a local date-time picker converted to UTC; default is now. Participants are comma-separated names. Title defaults to the first file's name.
10. **Plain-text mode** is chosen when the transcript has text but zero parsed turns. A transcript with a few timestamped lines inside free text is parsed as turns and the rest is ignored (existing parser behaviour). "Items have no timestamp links": extraction-side behaviour for transcripts without timestamps belongs to the extraction path (13.7) and was not touched; the viewer/`meetingLink` already handle a missing timestamp. — **Rami** (check with a real plain .txt).
11. **Client size limit is a constant (2 GB)**; the server limit (`RECORDING_MAX_BYTES`) is authoritative and answers 413 at presign. Alternative: expose the limit via an endpoint. — **@dev follow-up if the limit changes**.
12. **Story 7.8 closed as superseded**; pasting text directly is not implemented (save as .txt and upload).
13. **Gap — not verified against real S3/SeaweedFS**: signed-PUT with a signed `Content-Type` and browser CORS on the bucket (`PUT` + `Content-Type` header allowed from the frontend origin) are untested; unit tests use the in-memory fake. See the live test.
