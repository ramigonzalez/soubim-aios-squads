# Story 13.2 — Background Worker & Jobs Table

**Story ID:** 13.2
**Epic:** E13 — Recording Ingestion
**Priority:** High | **Effort:** 8 SP
**Status:** Ready for Review
**Type:** Feature (infrastructure)
**Requested by:** Rami — design the background worker

---

## Description

Slow steps (downloading a recording, extraction, later GPU transcription) run today inside the web process via FastAPI `BackgroundTasks` (`app/services/ingestion_pipeline.py`) — lost on restart, no retries, no status. Add a **jobs table in Postgres** and a **worker process** (same codebase, different start command) that picks jobs with `SELECT … FOR UPDATE SKIP LOCKED`. No Redis or extra service.

## Acceptance Criteria

- [x] `jobs` table (Alembic `007_story_13_2`): id, type, payload (JSONB), status (`queued` / `running` / `succeeded` / `failed`), attempts, max_attempts, run_after, locked_by, locked_at, last_error, source_id, organization_id, timestamps; index on (status, run_after)
- [x] Queue service `app/services/jobs.py`: `enqueue`, `claim_next` (`SELECT … FOR UPDATE SKIP LOCKED`), `mark_succeeded`, `mark_failed` (exponential backoff 30 s, 60 s, …; final failure after `max_attempts`), `requeue_stale` (running > 30 min → queued)
- [x] Worker `python -m app.worker`: handlers registry, permanent errors (`ExtractionError`, `PermanentJobError`, bad payload) fail at once, transient errors retry; on final failure the source is marked `failed` with the error; graceful stop on SIGTERM/SIGINT after the current job; stale-lock recovery every minute
- [x] Handlers: `process_source` (the ingestion pipeline — meetings, emails, documents); `fathom_import` (13.4) and `transcribe` (14.1) registered as not-implemented stubs
- [x] Approve, retry and batch approve **enqueue a job** instead of FastAPI `BackgroundTasks`
- [x] Ingestão → History lists approved sources still being processed with their job; badge shows **Na fila / Processando / Nova tentativa (n/m)** (last error as tooltip); history refreshes every 5 s while any source is processing
- [x] Local dev: `npm run dev` and `./dev.sh` start the worker; `npm run backend:worker`; `docker-compose` `worker` service
- [x] Tests: queue order, delayed jobs, backoff, final failure, permanent errors, stale requeue; **PostgreSQL concurrency test** (a locked job is skipped by another worker); worker end-to-end with a fake Claude client; routes enqueue; history shows the job; badge states (en + pt-BR)

## Dev Notes

```
Web API ──insert──▶ jobs (Postgres) ──claim (SKIP LOCKED)──▶ worker
                                                     ├─ fathom_import → storage (13.1)
                                                     ├─ transcribe    → GPU (14.1)
                                                     └─ extract       → Claude API (13.6)
```
- Replaces `BackgroundTasks` for ingestion; the existing state machine (`pending → approved → processed/failed`, Story 7.9) stays — `approved` now means "with the worker".
- **Scope vs 13.6:** the `process_source` handler already runs meeting extraction as a worker job (7.11 pipeline). 13.6 shrinks to its remaining criteria (cost logging per meeting in the UI, retry UX).
- **Without a running worker, approved sources stay "Na fila".** `npm run dev` / `./dev.sh` start it.
- Live check on the dev DB: worker claimed a job, failed it permanently ("not implemented yet (Story 14.1)"), stopped cleanly on SIGTERM ("finishing the current job, then stopping").
- Railway: the worker is a second service from the same repo (13.8).
