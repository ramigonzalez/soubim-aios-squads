# Story 7.19 — Tactiq Webhook Authentication Check

**Story ID:** 7.19
**Epic:** E7 — Multi-Source Ingestion Pipeline
**Status:** Ready for Review
**Type:** Security check
**Requested by:** Rami ("check it")

---

## What the endpoint verified before

`POST /api/webhooks/transcript` (`decision-log-backend/app/api/routes/webhooks.py`):

- The only real check was the global JWT middleware (`Authorization: Bearer`) plus `require_project_access(... WRITE)` on the payload's project. Without a user JWT the request is a 401.
- A `X-Tactiq-Signature` header parameter was declared but **never read**.
- `TACTIQ_WEBHOOK_SECRET` is a **required** setting (`app/config.py`), documented as a "webhook signature secret" in the README, but **no code used it**. A shared secret that nothing verified.

## Findings: what Tactiq supports

- Tactiq lists no native webhook feature. Its integrations collection (Dropbox, Confluence, Google Drive, HubSpot, Notion, Slack, Linear, Salesforce, Zapier, ...) has no webhook/API/signing article: <https://help.tactiq.io/en/collections/3091175-tactiq-integrations>
- The way to push a transcript to a custom URL is Zapier: Tactiq trigger "Meeting Transcript Is Ready", then the "Webhooks by Zapier" action (Custom Request / POST), which offers optional **Basic Auth** and **Headers** inputs: <https://zapier.com/apps/tactiq/integrations/webhook> and <https://help.tactiq.io/en/articles/10575233-tactiq-integration-for-zapier>
- Neither page documents a signature scheme (no HMAC header, no timestamp). Zapier's custom Headers let the sender add a **static** secret header.

Conclusion: no signature, timestamp or replay protection is available from the sender. Only a static shared secret in a header (or Basic Auth) is feasible.

## Decision (option b)

`verify_tactiq_secret()` in `webhooks.py`, called first in the route. Header `X-Tactiq-Secret` compared with `hmac.compare_digest` against `TACTIQ_WEBHOOK_SECRET`:

| Case | Result |
|---|---|
| header present and equal | continue (JWT and project access rules still apply) |
| header present and wrong | 401 in every environment |
| header absent, `ENVIRONMENT` = production/prod | 401 |
| header absent, dev/test | accepted (existing behaviour kept) |
| production and secret empty or the `.env.example` placeholder | 503 (fail closed) |

The secret is never logged or echoed. The unused `X-Tactiq-Signature` parameter was replaced by `X-Tactiq-Secret`.

Tests: `decision-log-backend/tests/unit/test_tactiq_webhook_auth.py` (12).

## Assumptions & gaps (pending)

- **Pending, Rami:** production behaviour change. Production callers must now send `X-Tactiq-Secret` and must set a real `TACTIQ_WEBHOOK_SECRET` (Railway), or the endpoint answers 401/503. Confirm nobody calls it today without the header.
- **Pending:** the endpoint still needs a user JWT (middleware), which a Zapier zap cannot refresh (7-day tokens). The secret is therefore an extra layer, not a replacement. Letting the secret alone authenticate (public path plus a service identity that picks an organization) was not done: it needs a design for which user/organization owns the created Source. Phase 2, ask @architect.
- **Unknown:** whether Tactiq has an undocumented or private API/webhook with signing; only public help-center and Zapier pages were checked. The Tactiq help pages were read through search summaries, not the full text.
- A static secret gives no replay protection; mitigated only by the existing `webhook_id` idempotency and TLS.
- Rotating the secret means updating the Zap header at the same time.
