# Story 7.18 — Backend Tests Run on a Throwaway Database

**Story ID:** 7.18
**Epic:** E7 — Multi-Source Ingestion Pipeline (test infrastructure)
**Priority:** Highest | **Effort:** 1 SP
**Status:** Ready for Review
**Type:** Bug
**Requested by:** Rami — after a full test run wiped the local dev database (2026-10-04)

---

## Problem Statement

Running the backend test suite deleted every table in the local dev database (`decisionlog`), including the D/SEASON pilot data. Two causes:

1. **`tests/conftest.py` used the dev database.** The TEST-003 fix (Story 5.1 QA: "PostgreSQL features not exercised") made fixtures auto-use `DATABASE_URL` from `.env.development` — the same database the app uses — and `drop_all` after every test. `TEST_DATABASE_URL=sqlite://` avoided it only if remembered.
2. **`tests/unit/test_database.py` bypassed the fixtures.** It used the app's own `engine` (always the dev database) and ran `drop_all` regardless of `TEST_DATABASE_URL`.

## Acceptance Criteria

- [x] Each test run creates a throwaway PostgreSQL database `decisionlog_test_<random>` on the configured server and drops it at the end (`pytest_unconfigure`); PostgreSQL features are still exercised (TEST-003 intent kept)
- [x] `DATABASE_URL` is pointed at the throwaway database before any app module is imported, so the app's engine/SessionLocal (services, middleware, `app.database.session` users) are redirected too
- [x] PostgreSQL unreachable → in-memory SQLite (app engine included)
- [x] Guard: `assert_test_database` refuses create/drop on any database not named `decisionlog_test*`; used by `db_session`, `pg_engine` and `test_database.py`'s fixture
- [x] `test_database.py` FK tests marked `@pytest.mark.postgresql` (SQLite does not enforce foreign keys — on main they only passed because they ran on the dev database)
- [x] Verified: full suite run with the dev Postgres up leaves the dev database unchanged (users/projects/items/sources/tables counted before and after) and leaves no `decisionlog_test_*` database behind
