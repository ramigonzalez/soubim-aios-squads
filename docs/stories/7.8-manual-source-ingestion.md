# Story 7.8 — Manual Source Ingestion (Paste & Extract)

**Story ID:** 7.8
**Epic:** E7 — Multi-Source Ingestion Pipeline
**Priority:** Highest | **Effort:** 5 SP (~2 days)
**Status:** Draft
**Type:** Feature
**Requested by:** Gabriela (pilot client) via Rami

---

## Problem Statement

The ingestion pipeline has three **automated** entry points (Tactiq webhooks, Gmail polling, Google Drive monitoring), all flowing through `Source → Curation → Approval → Claude Extraction → ProjectItems`. However, there is **no way** for a user to manually paste meeting notes, email content, or any text and have it processed through this same extraction pipeline.

The existing **ManualItemCreate** page (`/projects/:id/items/new`, Story 7.3) only creates **individual** ProjectItems directly — it bypasses Source creation and Claude extraction entirely. For a meeting with 15 decisions, the user would need to fill the form 15 times.

**Gabriela's need:** Paste raw meeting notes from a non-Tactiq meeting → Claude extracts all decisions, action items, topics, ideas automatically → items appear in project timeline after director approval. Same experience as automated sources, but initiated manually.

---

## User Story

**As a** project director,
**I want to** paste meeting notes or any text content into the system,
**So that** Claude can automatically extract decisions, action items, topics, and ideas — just like it does for automated sources — saving me from manually creating each item one by one.

## Architecture Decision

### Why Not Extend Story 7.3 (ManualItemCreate)?

Story 7.3's `ManualItemForm` creates **individual ProjectItems directly** — this is by design for quick, one-off captures. The manual source ingestion feature creates **Source records** that go through the full pipeline. These are fundamentally different flows:

| | Story 7.3 (Manual Item) | Story 7.8 (Manual Source) |
|---|---|---|
| **Creates** | 1 ProjectItem directly | 1 Source → N ProjectItems via Claude |
| **Pipeline** | Bypasses ingestion queue | Goes through approval → extraction |
| **Use case** | Quick single-item capture | Paste bulk notes, let AI extract |
| **Claude** | No extraction | Full extraction pipeline |
| **Approval** | Not needed | Director approval required |

Both features coexist — they serve different needs.

### Extraction Strategy for Manual Sources

The `process_approved_source()` function in `ingestion_pipeline.py` currently dispatches by `source_type`:
- `email` → `EmailExtractor`
- `document` → `DocumentExtractor`
- else → `extraction_v2.extract_items_from_transcript()` (meeting/default)

Since `manual_input` hits the `else` branch, it will **already use the meeting transcript extractor by default**. This is the correct behavior — pasted meeting notes are closest to transcript format. No changes needed in `ingestion_pipeline.py` for the extraction dispatch.

## Dev Notes

### Existing Infrastructure That Already Supports This

1. **Source model** (`models.py:251`): CHECK constraint already includes `'manual_input'` as valid `source_type`
2. **Ingestion pipeline** (`ingestion_pipeline.py:65`): `manual_input` falls into the `else` branch → uses `extraction_v2.extract_items_from_transcript()` — no dispatch changes needed
3. **AI summary service** (`summary_service.py`): Works on any `Source.raw_content` — source_type agnostic
4. **Ingestion API** (`ingestion.py`): `GET /ingestion` already returns sources of any type; approval/batch endpoints are type-agnostic
5. **Source curation** (`source_curation.py`): Optional Drive upload works for any source

### What This Story Actually Needs to Build

Only two things are truly new:
1. **One backend endpoint** (`POST /api/ingestion/manual`) to create the Source record
2. **One frontend form** (ManualSourceForm) + entry points (buttons on Ingestion and ProjectDetail pages)

Everything else (approval, extraction, display) already works because the pipeline is source-type agnostic.

### API Payload Example

```json
POST /api/ingestion/manual
{
  "title": "Site Visit Notes — March 4, 2026",
  "raw_content": "Met with contractor on site today. Key decisions:\n1. Foundation type: mat slab confirmed by structural team\n2. MEP routing: agreed to run main ducts through corridor ceiling\n3. Action: Rami to send updated drawings by Friday\n4. Topic: Need to revisit fire protection strategy for basement levels",
  "project_id": "uuid-of-project",
  "source_label": "Meeting Notes",
  "occurred_at": "2026-03-04T10:00:00Z"
}
```

Response:
```json
{
  "id": "uuid-of-new-source",
  "status": "pending"
}
```
