# Story 13.1 — Recording Storage (S3-Compatible)

**Story ID:** 13.1
**Epic:** E13 — Recording Ingestion
**Priority:** High | **Effort:** 5 SP (estimate)
**Status:** Draft
**Type:** Feature
**Requested by:** Rami — "save the recordings in Cloudflare R2"

---

## Description

Recordings are stored on the API server's disk today (`uploads/recordings/<source_id>.<ext>`, Story 7.13) — fine for one local pilot, not for production (761 MB per 98-min meeting, multiple servers, backups). Move recording storage to **private S3-compatible object storage**: SeaweedFS in local dev (Docker), Cloudflare R2 or Backblaze B2 in production — same code, different settings.

## Acceptance Criteria (draft)

- [ ] Storage service over the S3 API (boto3): put (multipart), stream-in from a URL, head, delete, signed GET link (expiring)
- [ ] Settings `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET`; bucket private (no anonymous access)
- [ ] Object keys namespaced by organization: `org/<org_id>/sources/<source_id>/recording.mp4`
- [ ] Meeting viewer streams from a **signed storage link** (Range/seek works) instead of `GET /api/recordings/{id}` from disk; access still checked before issuing the link (12.2)
- [ ] Size guard (configurable max per file and per organization) and lifecycle rule documented (e.g. delete originals N days after processing)
- [ ] `docker-compose.yml`: SeaweedFS service for local dev
- [ ] Migration script: move existing files from `uploads/recordings/` to storage

## Dev Notes

- **Proven by spike** (`data/tools/storage/s3_test.py`, 2026-10-05): private bucket (anonymous 403), Fathom → storage streaming without a local file, signed links with Range (206) and expiry, 761 MB multipart, browser seek to 33:40.
- MinIO no longer publishes free Docker images (Docker Hub and quay.io refused) — use `chrislusf/seaweedfs` with an `-s3.config` identities file.
- **Open decision:** production provider — R2 (no egress cost; needs a card on file even for the free 10 GB) vs Backblaze B2 (10 GB free). ~76 GB per 100 meetings ≈ $1/month either way. Optionally store audio-only (~50 MB/meeting) for processing.
- Reuse the signing pattern and tests from `app/services/recordings.py` / `tests/unit/test_meetings_api.py` (7.13).
